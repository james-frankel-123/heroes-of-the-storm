\section{Fused CUDA Kernels for MCTS Training}
\label{sec:cuda}

The MCTS training campaign in the main paper, 210 complete training runs (the submission's 195 and the revision's 15) spanning simulation budgets up to 800 per move and episode counts up to 1M, was only feasible because of the fused CUDA implementation described here. AlphaZero-style MCTS training is computationally demanding: each episode requires $\sim$8 MCTS searches of 200 simulations each, with a neural network forward pass at every leaf node. Standard implementations incur Python interpreter overhead, CUDA kernel launch latency, and host-device synchronization for each of the $\sim$3,200 forward passes per episode.

We developed a fused CUDA implementation that runs entire MCTS episodes inside a single kernel launch. One thread block (256 threads) executes one complete draft episode: thread~0 drives all sequential logic (UCB selection, action sampling, backpropagation) while all 256 threads cooperate on matrix multiplications during neural network forward passes via shared memory. The forward pass functions (\texttt{linear\_layer}, \texttt{batchnorm\_relu}, \texttt{residual\_block}) are compiled as \texttt{\_\_device\_\_} functions callable from within the kernel with zero launch overhead. Two additional optimizations compound with the fused kernel:
\begin{itemize}
    \item \textbf{Split backbone from heads}: Value symmetrization runs only the small value head (257$\to$128$\to$64$\to$1) twice rather than the full backbone, halving symmetrization cost.
    \item \textbf{Pipelined generation}: Episode results are written into pre-allocated ring buffers via C++ \texttt{memcpy}; a generation thread launches GPU batches asynchronously while the main thread performs gradient updates.
\end{itemize}

Table~\ref{tab:throughput} shows the progression; all stages measured at 200 simulations per move. The first four rows are development-time measurements taken as each optimization landed; the final row is the sustained steady-state rate of the finished implementation, measured across the submission's training campaign (195 complete runs, 128 concurrent episodes per kernel launch) under four-GPU load on NVIDIA RTX PRO 6000 Blackwell Workstation Edition GPUs (96~GB each). The gap between the bring-up and final figures reflects cumulative-average warm-up in early measurements and subsequent batching maturity. Sustained throughput is 117$\times$ the Python baseline and scales inversely with simulation budget (74 episodes/second at 400 simulations per move), so the implementation is limited by compute, with little fixed overhead: a 300K-episode run completes in under 40 minutes on one GPU. Each episode requires $\sim$1~MB of global memory for the MCTS tree (2,048 nodes); with 128 concurrent episodes per kernel launch, total GPU memory usage is $\sim$140~MB plus 10~MB of network weights.

\paragraph{Apples-to-apples baseline.} For a controlled speedup claim we built a tuned host-tree baseline in the style of KataGo's batched-evaluation pipelines: 64--256 CPU threads each running one episode's tree, leaf evaluations batched across threads onto the GPU via cuBLAS GEMM over multiple streams, reproducing the production kernel's exact per-simulation work (policy priors at expansion, Generic Draft rollout to terminal at every leaf, symmetrized enriched-WP scoring). At equal work \textit{and} equal search semantics (leaf batch 1; first-turn root-visit total-variation distance from the kernel 0.047, at the 0.044 kernel-vs-kernel seed-noise floor; win rate vs.\ GD 0.761 vs.\ the kernel's 0.757), the host pipeline sustains 68 ep/s against the fused kernel's 151 ep/s on the same GPU: the fused kernel is 2.2$\times$ faster, the figure quoted in the main paper, because per-simulation host-device round trips cannot be amortized without within-episode leaf batching. Virtual-loss leaf batching does push the host pipeline to 163 ep/s (1.07$\times$ the kernel), but only by degrading the search itself: at leaf batch 32 the win rate vs.\ GD falls from 0.757 to 0.531 and the visit-distribution TV rises to 0.62; softening virtual loss to 0.25 recovers only 0.712. Per-component profiling shows the GD rollout evaluation dominates ($\sim$75\% of the host pipeline's evaluator wait time; policy priors and WP scoring share the rest), and that the kernel's per-node cache of opponent GD distributions is dead code in practice: leaves expand only at our-team steps, so cached nodes are never re-traversed at opponent steps (measured cache-miss count 0), which is why it is not listed among the optimizations above. The remaining advantages of the fused kernel are operational: 0.12~s startup, a deterministic $\sim$270~MB footprint, and no host thread pool or Python runtime at inference.

\paragraph{Assigned win rate} Synthetic rows get out-of-fold features like real rows, but their labels are adjusted with the deploy statistics (pairwise counter and synergy), so the realized mean label differs from the assigned rate: 4.9\%, 5.0\%, 9.5\%, and 29.9\% for assigned 0, 5, 10, and 50\%. \paragraph{Scope}

Held-out accuracy stays at 57.5--57.7\% and post-snapshot calibration slope at 0.93--1.02 in every cell, and 24--27 of 28 sanity tests pass. Within augmentation, the five-tank effect comes from the unseen compositions, and lower assigned win rates penalize five tanks more.

The main paper's interaction-awareness metrics are built from the pairwise synergy and counter deltas (Section~III of the main paper), which subtract from each observed pair win rate an independence expectation formed from the two heroes' individual win rates. We validate that these deltas carry real outcome signal by scoring each side of real drafts with the exact metric implementations against the game's actual outcome. Pooled naively, the decile curves are not monotone: subtracting the individual-strength expectation makes the deltas strongly anti-correlated with team hero strength ($r = -0.87$ between team synergy delta and team mean hero win rate), so teams of individually strong heroes receive negative deltas while still winning more. We therefore control for that component, computing deciles within tier and own/opposing team-strength strata.

The submission ran this check on the 38,981 test replays with the external statistics, which contain those replays' own outcomes (first row of Table~\ref{tab:metricvalid}). On 291,837 post-snapshot games, which were uploaded after the statistics were pulled and so cannot be in them, the same statistics give spreads of +9.1pp (synergy) and +8.0pp (counter), both monotone across all nine steps. The published spreads are 1.5pp and 1.7pp larger, about 16\% and 21\% of the clean values, though the two figures come from different game sets. Statistics built only from our training split give the same qualitative result on both game sets. The interaction deltas measure an outcome-relevant property of a composition beyond individual hero strength, which is the component they are designed to isolate. 

\section{Dual-Snapshot Stability of the Interaction Metrics}

The collapse diagnosis and the method comparisons rest instead on \textit{relative} gaps. Here we verify directly that the relative ordering of strategies is stable across statistics snapshots.

\section{External Validation on Coordinated-League Drafts}
\label{sec:ngs}

The main paper's behavior policy is uncoordinated ranked-ladder play, and its Limitations note that every evaluation shares that corpus. As an external test, we evaluate the frozen snapshot-trained win-probability models on drafts from the Nexus Gaming Series (NGS), an amateur organized league in which persistent five-player teams draft together with dedicated captains. Scanning the Heroes Profile NGS archive yielded 11{,}132 games, of which \textbf{11{,}034} pass filtering (patch 2.55, complete 16-step draft, known winner), spanning 2021--2026 across ten season clusters, the same patch era as our ladder corpus.

\paragraph{Coordinated drafts are \textit{more} meta-concentrated.} A natural hypothesis is that coordinated teams, freed from solo-queue comfort picking, explore more of the hero pool. The data show the opposite, at both the hero and the composition level. Hero level: NGS pick entropy is 5.92 bits vs.\ the ladder's 6.25 (effective pool 60.5 vs.\ 75.9 heroes), the top-10 heroes take 33.5\% of picks vs.\ 25.1\%, and the off-meta share (picks outside the ladder top-30) is 39.8\% vs.\ 43.3\%; hero pick-rate rank correlation between the populations is 0.74. Composition level: NGS fields 78 distinct role compositions vs.\ 238 on ladder, with composition entropy 2.69 vs.\ 3.06 bits, the top-5 compositions covering 84.3\% vs.\ 78.6\% of teams, and 90\% coverage reached in 9 vs.\ 12 compositions. The modal composition is the same standard core in both populations (bruiser/healer/double-ranged/tank: 53\% vs.\ 50\%); NGS's second-most-common composition is a double-tank variant (12.3\%). Our reading: coordinated teams converge on a known-good playbook, while ladder ``diversity'' partly reflects uncoordinated comfort picking and error. This fits the main paper's description of the behavior policy as shaped largely by social habit. Coordinated teams draft more narrowly, so the ladder's wider spread reflects comfort picking more than exploration.

\paragraph{Win-probability transfer.} Scored at the game level with symmetrized predictions, the leak-free enriched model reaches 55.5\% accuracy on NGS (95\% CI $\pm$0.9pp) against 57.7\% on the held-out ladder test set; the leak-free naive and augmented models also score 55.5\%. NGS games are in neither our corpus nor the Storm League aggregates, so no model has self-inclusion here. The ladder-to-NGS drop is about 2.2pp for every model. The submission compared NGS with a leaky ladder figure (58.1\%) and reported a larger drop for the enriched model; its enriched model also scored 55.5\% on NGS, with calibration slope 0.75 against 0.86 for the leak-free enriched model and 0.94 for the leak-free naive model. Splitting NGS drafts into quartiles by off-meta pick share, the submitted enriched model scored 57.6\% on the most-meta quartile and 54.5\% on the least-meta quartile. The leak-free models show no such trend: the enriched model scores 56.0\%, 54.2\%, 56.9\%, and 54.8\% from most- to least-meta quartile (about 2,760 games each, CI $\pm$1.9pp), and the naive model 56.4\%, 54.7\%, 56.2\%, and 54.5\%. We therefore do not claim that the degradation concentrates in off-meta drafts. 99.98\% of NGS team compositions fall within the composition sets observed in the ladder-era aggregate statistics, so this shift re-weights familiar structures and does not reach the never-observed compositions that synthetic augmentation targets. One caveat caps interpretation: NGS outcomes also reflect persistent team-strength imbalances that the models never observe (the same organized teams meet repeatedly), which lowers attainable accuracy in a way not directly comparable to solo-queue ladder play.

\section{Draft Concentration and Out-of-Distribution Extrapolation}
\label{sec:concentration}

How far do the agents drift from human play? We measure the leak-free operating-point agent (F\_oof, 5 seeds $\times$ 1,000 benchmark drafts, mid tier, 200 inference simulations, root temperature 1) and, for comparison, the submission's J\_800sim (5 seeds).

\paragraph{Concentration} Each F\_oof seed uses 24--27 distinct heroes at 3.25--3.59 bits of pick entropy; pooling the five seeds gives 3.58 bits, so the seeds converge on one head. Its seven favorite heroes are Samuro, Rehgar, Hogger, Deathwing, Falstad, Illidan, and Ragnaros; the submitted J\_800sim's head overlaps heavily (Hogger, Samuro, Rehgar, Deathwing, Auriel, Illidan, Leoric) and is slightly more diverse (29--32 heroes, 3.74 bits pooled).

\paragraph{Are the favorites' interactions real?} For all 21 pairs and 35 trios of the seven favorites we compare the win rate of real teams containing them with the independence expectation from the heroes' own win rates (the paper's synergy convention). In our training split the favorite pairs beat independence by +0.54pp ($n$ = 228,342 team-games, $z$ = 5.2) and the trios by +1.70pp ($n$ = 12,767, $z$ = 3.8). On 450,445 post-snapshot games (including the drifted 2.55.17 builds), which no model saw, the pairs beat it by +0.21pp ($n$ = 56,029, $z$ = 1.0) and the trios by +1.68pp ($n$ = 3,169, $z$ = 1.9). The trio edge replicates in size but not yet in significance; the pair edge shrinks by more than half. For the submitted agent's favorites the forward edges are similar (+0.26pp pairs, +1.35pp trios, both not significant). The submission's statement that search ``exploits precisely the interactions the data certifies'', based on in-sample checks only, is withdrawn.

\paragraph{Where the agent leaves the data} None of F\_oof's ten most frequent five-hero teams (together 38.8\% of its drafts) occurs even once in the 1.95M-game corpus. One level up it stays in familiar territory: 98.7\% of its drafts land on role compositions admitted to our own composition table (at least 50 games in the tier label) and 63.7\% on compositions with at least 1,000 games.

\section{Leakage Mechanism: A Within-Snapshot Split Experiment}
\label{sec:split}

To isolate how in-sample statistics affect a value function and the search that optimizes it, without any balance drift, we split the pinned snapshot by a salted replay-level hash into halves A and B. Proxies, their statistics, their early stopping, and any search against them use only half A; references are built only from half B (three out-of-fold enriched judges, a hero-identity judge, and a cross-fitted realized-outcome index), plus the post-snapshot index and the Quick Match judge.

Table~\ref{tab:split} shows the mechanism. In-sample statistics make the value function overconfident on games outside them (slope 0.61 at 975K games, 0.17 at 122K) and less accurate, while reporting inflated accuracy on its own validation rows. Out-of-fold statistics remove the effect. Width, depth, dropout, weight decay, and training length each move held-out accuracy by less than 0.2pp, with one exception: 40 epochs with no regularization (slope 0.40). Leakage dominates every capacity knob. ``Own-split'' accuracy is that of the last epoch.

Search then exploits the error. With a behavioral-cloning prior and argmax root selection, raising search from 1,024 to 16,384 simulations lifts the in-sample proxy's own score from 0.780 to 0.848 and its half-B judges from 0.631 to 0.666; the out-of-fold proxy, whose own score (0.673 $\to$ 0.734) tracks the judges almost one for one, reaches 0.661 $\to$ 0.713 on the same judges and higher values on every realized index. A small in-sample proxy (1/8 of A) shows classic over-optimization: its own score climbs to 0.932 while the half-B judges stop improving after 4,096 simulations (0.009 and 0.004 lower at 16,384, about two standard errors or less). A leak-free proxy trained on 1/8 of the data beats an in-sample proxy with 8$\times$ the data on both realized indices. In the paper's own self-play pipeline on half A (2 seeds per cell; the 800-simulation runs stopped at about 30\% of training; the behavioral-cloning prior and GD bootstrap were trained on the full snapshot, so they saw half B), raising training simulations from 200 to 800 at matched episodes moves the in-sample proxy's references down by 0.02--0.05 and the out-of-fold proxy's references up by 0.01--0.03.

Two diagnostics that did not detect the problem: the per-draft disagreement of a 4-seed ensemble trained on the same statistics stays between 0.005 and 0.007 at every search pressure (seeds share the leak), and pessimistic lower-confidence-bound search using that disagreement moves the references by at most 0.007. Held-out calibration slope did detect it, which is why the main paper reports it for every value function and judge.

\section{Composition Blind Spot and Corrected References}
\label{sec:compjudge}

\paragraph{Audit} A drafter that picks the available hero with the highest win rate scored 0.677 under the production seed-selection judge (a realized index on 90 days of games), above both trained policies (0.644, 0.650), although 55\% of its teams were degenerate. Table~\ref{tab:compaudit} measures every reference on the 1,949,087 snapshot games, which none of them trained on, as realized minus predicted win rate per team type (no healer, no frontline, three or more of a stacking role; exclusive, in that order). Normal teams are calibrated to within 0.13pp. Degenerate teams lose 4--7pp more often than RN, gN-naive, R17, and both Quick Match judges predict; the gap survives a global slope and intercept recalibration of each judge. gN, which reads role-count features, misses 3.0pp (1.6pp in its first version, which also read the external composition table). The post-snapshot no-drift games give the same picture with held-out predictions (gN from two-fold refits of its recipe: $-$2.5pp; RN cross-fitted: $-$5.2pp; consensus $-$4.5pp). RN is blind because its composition term is a per-role-multiset win rate shrunk toward 50\% with a 200-game prior, and degenerate multisets hold a median of 2.5 (stack) to 10 (no frontline) games; gN-naive must learn the penalty from hero identities alone; the QM judges learned from a mode with a different team-assembly process.

\paragraph{Selection or cause} Weaker players might field broken teams. We joined 918,922 games (snapshot games from June 2025 and post-snapshot games with all ten player records) to causal per-player, per-hero skill estimates from the previous day (a Gaussian-process model over each player's heroes; skill is estimated with degenerate-team games left out, so it cannot absorb the penalty itself) and to pick order. Degenerate teams are weaker (summed skill $-$0.3pp vs.\ +1.0pp for normal teams), but matchmaking pairs them with weaker opponents too, and the within-game skill gap is only $-$0.24pp. Against RN, the penalty is $-$4.80pp with no controls, $-$4.63pp with the team skill difference, $-$4.84pp adding skill by pick position and first-pick side, and $-$4.66pp adding party and never-played-hero counts (bootstrap SE 0.27pp; SE of the change 0.05pp). At most about 0.2pp of the 4.8pp is selection on these measures. Unmeasured differences between players remain possible.

\paragraph{Correction} For each reference $J$ we fit $p^\ast = \sigma(\mathrm{logit}\,p_J + \beta_J^\top(s_\text{own} - s_\text{opp}))$ with $s$ the three structure indicators (non-exclusive) and $p_J$ fixed, on the 291,837 post-snapshot no-drift games, using predictions $J$ makes for games it did not train on (above). The fitted no-healer, no-frontline, and stack coefficients (logits) are $-$0.10, $-$0.11, $-$0.10 (gN); $-$0.22, $-$0.20, $-$0.35 (gN-naive); $-$0.18, $-$0.24, $-$0.36 (RN); $-$0.23, $-$0.17, $-$0.27 (QM2026). The correction is antisymmetric in the two teams, so symmetrized scores stay symmetrized. A version with the skill controls gives coefficients within 0.07 and over-corrects the snapshot games by 0.6pp, consistent with little selection; we use the plain fit. Adding the same indicators inside RN's own cross-fitted logistic gives the same result (degenerate gap $-$0.1 $\pm$ 0.4pp on a 25\% snapshot sample, log loss 0.68595 $\to$ 0.68572). On games after the 2.55.17 balance patch the penalty is smaller and the corrected references over-charge degenerate teams by about 2pp; a first fit on those games under-corrected the snapshot by 1.6pp. The terms are learned from human degenerate teams, 93\% of which have exactly one defect (68\% no healer); the MCTS agents' degenerate teams have exactly one defect in 95--100\% of cases and are 72--98\% no-healer teams, the best-covered type. A structure nobody fields, such as five tanks, receives only the sum of its indicators.

\paragraph{Effect on the results} Under the corrected references, the contrasts behind sim scaling, the feature gap, and the operating point change by at most 0.004 (Table~\ref{tab:compclaims}): GD opponents sampled at temperature 1 are themselves 12--13\% degenerate, so the correction charges both sides of the MCTS benchmark. In the tournament the constrained agents gain (constrained vs.\ unconstrained MCTS 0.499 $\to$ 0.509, masked vs.\ unmasked greedy 0.500 $\to$ 0.512, both $\pm$0.003), the Gourdeau estimator (46\% degenerate) drops from 0.531 to 0.512, MCQ from 0.330 to 0.310, and rank agreement within the top six rises (QM judges 0.77 $\to$ 0.83). The matched head to head of the submitted J\_800sim\_s9 checkpoint (drafts not stored) moves from 0.503 to about 0.514 when the stored degenerate counts are charged.

\paragraph{Composition table of gN} The first version of gN read the external composition table for 4 of its 283 inputs. That table aggregates games that overlap our snapshot. We rebuilt gN with a composition table from its own post-snapshot games (out of fold for training rows), so it shares no statistic with any agent; the submitted value functions read the external table dated March 2026. The rebuilt gN has test accuracy 55.2\% and slope 1.01 (55.3\% and 0.97 before). It scores the agents 0.009 lower on average and B\_fullwp, which optimized the external table, 0.015 lower. Contrasts that move by more than 0.003: F\_400sim $-$ B\_fullwp +0.018 $\to$ +0.025, B\_fullwp $-$ K\_truebase $-$0.009 $\to$ $-$0.015, J\_oof $-$ F\_oof $-$0.007 $\to$ $-$0.011, and C\_large $-$ B\_fullwp +0.009 $\to$ +0.014. Tournament standings move by at most 0.007 under gN and 0.002 under the consensus.

\section{Judge Attenuation}
\label{sec:atten}

An independent judge is a noisier model than the value function an agent optimized, so a real gain shrinks under it. As a benchmark for that shrinkage we regress each judge's prediction on the value function's prediction over the 38,981 test replays, which neither trained on (Table~\ref{tab:atten}). With no over-optimization, a gain $d$ under the value function should appear as about slope $\times\, d$ under the judge, if the value function's errors on agent drafts resemble its errors on human drafts. The submitted value function's statistics contain the test games, so its slopes are a rough guide.

\section{Feature-Group Sweep (Fractional Factorial)}
\label{sec:sweep}

The submission's sweep trained all $2^{10}$ subsets of ten feature groups at two architectures and two learning rates (4,096 configurations) with features that contained the test games' outcomes. The revision re-runs the question with leak-free statistics using a $2^{10-3}$ fractional factorial: base factors map\_type, role\_counts, hero\_wr, team\_avg\_wr, hero\_map\_wr, map\_delta, pairwise\_counters (A--G), and generated factors pairwise\_synergies $=$ ABCD, counter\_detail $=$ ABEF, synergy\_detail $=$ ACEG. Every word of the defining relation has length at least 5 (resolution V), so main effects are unaliased with each other and with all two-factor interactions, and each main effect equals the full-factorial marginal the submission reported, up to four-factor and higher interactions. Each of the 128 configurations trains one 256$\to$128 model (seed 42, learning rate $5\times10^{-4}$, validation early stopping). Effect SE, from the residual after fitting main effects: 0.02pp (test accuracy), 0.01pp (post-snapshot accuracy), $5\times10^{-5}$ (post-snapshot log-loss).

\section{Offline RL: Sweeps and Robustness}
\label{sec:cqlrobust}

The main paper's Table~V shows one or two cells per offline-RL family. The full sweeps, run on the pinned snapshot with naive (identity) features unless noted, all end at an anchored policy. CQL across $\alpha \in \{0.1, 0.5, 1, 2, 5\}$ (5 seeds $\times$ 1000 drafts each): 93.0--99.9\% healer and 2.2--13.4\% degenerate, best at $\alpha = 2$ (99.8\%, 2.2\%). BC-regularized CQL across $\beta \in \{0.1, 0.5, 1, 2\}$: near-perfect safety, high GD agreement, negative synergy. MCQ across $\tau \in \{0.4, \dots, 0.8\}$: for $\tau \geq 0.6$ the penalty is inactive and the policy uses the same $\sim$9 heroes regardless of context; $\tau = 0.5$ gives the dead-network policy of the main text (all 256 and 128 units of hidden layers 2 and 3 output zero on 200,000 held-out states; at $\tau = 0.6$ layer 3 is fully dead; a CQL $\alpha = 1$ control has 22 and 16 dead units). IQL across a $\tau \times \beta$ grid of six cells: statistically identical cells, advantage weights 0.998--0.999, Q-network held-out loss 0.6948 against $\ln 2 = 0.6931$ for a constant.

\textit{Capacity and target-update robustness.} At $\alpha = 1$ we crossed three network sizes (256$\to$128$\to$64, 512$\to$256$\to$128, 1024$\to$512$\to$256) with five target-network update rates ($\tau_{\text{target}} \in \{0.001, 0.005, 0.01, 0.05, 0.1\}$; 200 drafts each). Across all 15 configurations the collapse signals are stable: healer 98.0--100\%, degenerate 0.5--2.5\%, 43--52 distinct heroes, entropy 4.25--4.52 bits, GD agreement 69.0--77.3\%, synergy $-$0.08 to +0.02. No configuration is interaction-aware, and the update rate is inert, as expected with Monte Carlo returns (no bootstrapping).

\textit{CQL with enriched features.} Retrained leak-free (out-of-fold enriched transition features, early stopping on the validation split) and evaluated with deploy statistics, enriched CQL is slightly safer than naive CQL (0.4--2.1\% degenerate) and changes nothing else: synergy $-$0.18 to $-$0.19, entropy 4.44--4.47 bits, GD agreement 71.0--73.3\%. The submission's versions, trained on the external statistics, gave the same picture (68.6--73.7\% GD agreement). Under the independent references these agents score 0.50--0.53 against behavioral-cloning opponents.
