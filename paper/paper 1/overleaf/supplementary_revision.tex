\section{Fused CUDA Kernels for MCTS Training}
\label{sec:cuda}

The MCTS training campaign in the main paper, 210 complete training runs (the submission's 195 and the revision's 15) spanning simulation budgets up to 800 per move and episode counts up to 1M, was only feasible because of the fused CUDA implementation described here. AlphaZero-style MCTS training is computationally demanding: each episode requires $\sim$8 MCTS searches of 200 simulations each, with a neural network forward pass at every leaf node. Standard implementations incur Python interpreter overhead, CUDA kernel launch latency, and host-device synchronization for each of the $\sim$3,200 forward passes per episode.

We developed a fused CUDA implementation that runs entire MCTS episodes inside a single kernel launch. One thread block (256 threads) executes one complete draft episode: thread~0 drives all sequential logic (UCB selection, action sampling, backpropagation) while all 256 threads cooperate on matrix multiplications during neural network forward passes via shared memory. The forward pass functions (\texttt{linear\_layer}, \texttt{batchnorm\_relu}, \texttt{residual\_block}) are compiled as \texttt{\_\_device\_\_} functions callable from within the kernel with zero launch overhead. Two additional optimizations compound with the fused kernel:
\begin{itemize}
    \item \textbf{Split backbone from heads}: Value symmetrization runs only the small value head (257$\to$128$\to$64$\to$1) twice rather than the full backbone, halving symmetrization cost.
    \item \textbf{Pipelined generation}: Episode results are written into pre-allocated ring buffers via C++ \texttt{memcpy}; a generation thread launches GPU batches asynchronously while the main thread performs gradient updates.
\end{itemize}

Table~\ref{tab:throughput} shows the progression; all stages measured at 200 simulations per move. The first four rows are development-time measurements taken as each optimization landed; the final row is the sustained steady-state rate of the finished implementation, measured across the submission's training campaign (195 complete runs, 128 concurrent episodes per kernel launch) under four-GPU load on NVIDIA RTX PRO 6000 Blackwell Workstation Edition GPUs (96~GB each). The highest rate recorded in the training logs is 161 episodes/second. The rows are heterogeneous in leaf evaluation (development history, not a controlled comparison); the controlled comparison appears below. The gap between the bring-up and final figures reflects cumulative-average warm-up in early measurements and subsequent batching maturity. Sustained throughput is 117$\times$ the Python baseline and scales inversely with simulation budget (74 episodes/second at 400 simulations per move), so the implementation is limited by compute, with little fixed overhead: a 300K-episode run completes in under 40 minutes on one GPU. Each episode requires $\sim$1~MB of global memory for the MCTS tree (2,048 nodes); with 128 concurrent episodes per kernel launch, total GPU memory usage is $\sim$140~MB plus 10~MB of network weights.

\paragraph{Apples-to-apples baseline.} For a controlled speedup claim we built a tuned host-tree baseline in the style of KataGo's batched-evaluation pipelines: 64--256 CPU threads each running one episode's tree, leaf evaluations batched across threads onto the GPU via cuBLAS GEMM over multiple streams, reproducing the production kernel's exact per-simulation work (policy priors at expansion, Generic Draft rollout to terminal at every leaf, symmetrized enriched-WP scoring). At equal work \textit{and} equal search semantics (leaf batch 1; first-turn root-visit total-variation distance from the kernel 0.047, at the 0.044 kernel-vs-kernel seed-noise floor; win rate vs.\ GD 0.761 vs.\ the kernel's 0.757), the host pipeline sustains 68 ep/s against the fused kernel's 151 ep/s on the same GPU: the fused kernel is 2.2$\times$ faster, the figure quoted in the main paper, because per-simulation host-device round trips cannot be amortized without within-episode leaf batching. Virtual-loss leaf batching does push the host pipeline to 163 ep/s (1.07$\times$ the kernel), but only by degrading the search itself: at leaf batch 32 the win rate vs.\ GD falls from 0.757 to 0.531 and the visit-distribution TV rises to 0.62; softening virtual loss to 0.25 recovers only 0.712. Per-component profiling shows the GD rollout evaluation dominates ($\sim$75\% of the host pipeline's evaluator wait time; policy priors and WP scoring share the rest), and that the kernel's per-node cache of opponent GD distributions is dead code in practice: leaves expand only at our-team steps, so cached nodes are never re-traversed at opponent steps (measured cache-miss count 0), which is why it is not listed among the optimizations above. The remaining advantages of the fused kernel are operational: 0.12~s startup, a deterministic $\sim$270~MB footprint, and no host thread pool or Python runtime at inference.

The main paper's interaction-awareness metrics are built from the pairwise synergy and counter deltas (Section~III of the main paper), which subtract from each observed pair win rate an independence expectation formed from the two heroes' individual win rates. We validate that these deltas carry real outcome signal by scoring each side of real drafts with the exact metric implementations against the game's actual outcome. Pooled naively, the decile curves are not monotone: subtracting the individual-strength expectation makes the deltas strongly anti-correlated with team hero strength ($r = -0.87$ between team synergy delta and team mean hero win rate), so teams of individually strong heroes receive negative deltas while still winning more. We therefore control for that component, computing deciles within tier and own/opposing team-strength strata.

The submission ran this check on the test replays with the external statistics, which contain those replays' own outcomes (first row of Table~\ref{tab:metricvalid}). On 260,539 post-snapshot games, which were uploaded after the statistics were pulled and so cannot be in them, the same statistics give spreads of +8.8pp (synergy) and +9.2pp (counter), both monotone across all nine steps. The self-including spreads are 2.5pp and 1.8pp larger, about 28\% and 20\% of the clean values, though the two figures come from different game sets. Statistics built only from our training split give the same qualitative result on both game sets. The interaction deltas measure an outcome-relevant property of a composition beyond individual hero strength, which is the component they are designed to isolate.

\section{External Validation on Coordinated-League Drafts}
\label{sec:ngs}

The main paper's behavior policy is uncoordinated ranked-ladder play, and its Limitations note that every evaluation shares that corpus. As an external test, we evaluate the frozen snapshot-trained win-probability models on drafts from the Nexus Gaming Series (NGS), an amateur organized league in which persistent five-player teams draft together with dedicated captains. Scanning the Heroes Profile NGS archive yielded 11{,}132 games, of which \textbf{11{,}034} pass filtering (patch 2.55, complete 16-step draft, known winner), spanning 2021--2026 across ten season clusters, the same patch era as our ladder corpus.

\paragraph{Coordinated drafts are \textit{more} meta-concentrated.} A natural hypothesis is that coordinated teams, freed from solo-queue comfort picking, explore more of the hero pool. The data show the opposite, at both the hero and the composition level. Hero level: NGS pick entropy is 5.92 bits vs.\ the ladder's 6.25 (effective pool 60.5 vs.\ 75.9 heroes), the top-10 heroes take 33.5\% of picks vs.\ 25.1\%, and the off-meta share (picks outside the ladder top-30) is 39.8\% vs.\ 43.3\%; hero pick-rate rank correlation between the populations is 0.74. Composition level: NGS fields 78 distinct role compositions vs.\ 238 on ladder, with composition entropy 2.69 vs.\ 3.06 bits, the top-5 compositions covering 84.3\% vs.\ 78.6\% of teams, and 90\% coverage reached in 9 vs.\ 12 compositions. The modal composition is the same standard core in both populations (bruiser/healer/double-ranged/tank: 53\% vs.\ 50\%); NGS's second-most-common composition is a double-tank variant (12.3\%). Our reading: coordinated teams converge on a known-good playbook, while ladder ``diversity'' partly reflects uncoordinated comfort picking and error. This fits the main paper's description of the behavior policy as shaped largely by social habit. Coordinated teams draft more narrowly, so the ladder's wider spread reflects comfort picking more than exploration.

\paragraph{Win-probability transfer.} Scored at the game level with symmetrized predictions, the leak-free enriched model reaches 55.4\% accuracy on NGS (95\% CI $\pm$0.9pp) against 57.5\% on the held-out ladder test set; the leak-free naive model also scores 55.4\%. NGS games are in neither our corpus nor the Storm League aggregates, so no model has self-inclusion here. The ladder-to-NGS drop is 2.1--2.2pp for both models. The submission compared NGS with a leaky ladder figure (58.0\% on our test set) and reported a larger drop for the enriched model; its enriched model scores 55.5\% on NGS, with calibration slope 0.75 against 0.85 for the leak-free enriched model and 0.91 for the leak-free naive model. The submission also reported that the degradation concentrates in off-meta drafts. Splitting NGS drafts into quartiles by off-meta pick share, the leak-free models show no such trend: the enriched model scores 56.8\%, 54.3\%, 55.7\%, and 54.7\% from most- to least-meta quartile (about 2,760 games each, CI $\pm$1.9pp), and the naive model 57.0\%, 53.9\%, 55.9\%, and 54.8\%. We therefore do not claim that the degradation concentrates in off-meta drafts. 99.98\% of NGS team compositions fall within the composition sets observed in the ladder-era aggregate statistics, so this shift re-weights familiar structures and does not reach the never-observed compositions. One caveat caps interpretation: NGS outcomes also reflect persistent team-strength imbalances that the models never observe (the same organized teams meet repeatedly), which lowers attainable accuracy in a way not directly comparable to solo-queue ladder play.

\section{Draft Concentration and Out-of-Distribution Extrapolation}
\label{sec:concentration}

How far do the agents drift from human play? We measure the operating-point agent (F, 5 seeds $\times$ 1,000 benchmark drafts, mid tier, 200 inference simulations, root temperature 1) and, for comparison, J (800 training simulations, 5 seeds).

\paragraph{Concentration} Each F seed uses 22--26 distinct heroes at 3.24--3.52 bits of pick entropy; pooling the five seeds gives 33 heroes and 3.54 bits, so the seeds converge on one head. Its seven favorite heroes are Samuro, Rehgar, Hogger, Deathwing, Falstad, Artanis, and Abathur; J's head overlaps heavily (Hogger, Samuro, Rehgar, Deathwing, Illidan, Cho, Auriel) and is slightly more diverse (26--31 heroes per seed, 3.61 bits pooled).

\paragraph{Are the favorites' interactions real?} For all 21 pairs and 35 trios of the seven favorites we compare the win rate of real teams containing them with the independence expectation from the heroes' own win rates (the paper's synergy convention). In our training split the favorite pairs beat independence by +0.36pp ($n$ = 273,540 team-games, $z$ = 3.8) and the trios by +1.16pp ($n$ = 17,771, $z$ = 3.1). On 414,926 post-snapshot games (including the drifted 2.55.17 builds), which no model saw, the pairs beat it by +0.09pp ($n$ = 60,675, $z$ = 0.4) and the trios by +0.75pp ($n$ = 4,013, $z$ = 1.0). Neither edge replicates. J's favorites do somewhat better forward (+0.55pp pairs, $z$ = 1.9; +1.90pp trios, $z$ = 1.1), still short of significance. The submission's statement that search ``exploits precisely the interactions the data certifies'', based on in-sample checks only, is withdrawn.

\paragraph{Where the agent leaves the data} None of F's ten most frequent five-hero teams (together 41.2\% of its drafts) occurs even once in the 1.94M-game corpus. One level up it stays in familiar territory: 96.9\% of its drafts land on role compositions admitted to our own composition table (at least 50 games in the tier label) and 47.4\% on compositions with at least 1,000 games.

\section{Leakage Mechanism: A Within-Snapshot Split Experiment}
\label{sec:split}

To isolate how in-sample statistics affect a value function and the search that optimizes it, without any balance drift, we split the ranked snapshot by a salted replay-level hash into halves A and B. Proxies, their statistics, their early stopping, the behavioral-cloning prior and opponent of the search, and any search against them use only half A; references are built only from half B (three out-of-fold enriched judges, a hero-identity judge, and a cross-fitted realized-outcome index), plus the post-snapshot index and the Quick Match judge.

Table~\ref{tab:split} shows the mechanism. In-sample statistics make the value function overconfident on games outside them (slope 0.62 at 952K games, 0.17 at 119K) and less accurate, while reporting inflated accuracy on its own validation rows. Out-of-fold statistics remove the effect. Width, depth, dropout, weight decay, and training length each move held-out accuracy by at most 0.1pp, except training without regularization for 10 or 40 epochs ($-$0.3pp and $-$1.0pp; slope 0.57 and 0.40). Leakage dominates every capacity knob.

Search then exploits the error. With a behavioral-cloning prior and argmax root selection, raising search from 1,024 to 16,384 simulations lifts the in-sample proxy's own score from 0.754 to 0.834 and its half-B judges from 0.644 to 0.671; the out-of-fold proxy, whose own score (0.680 $\to$ 0.740) tracks the judges almost one for one, reaches 0.660 $\to$ 0.721 on the same judges and higher values on every realized index (half-B index 0.659 vs.\ 0.628, post-snapshot index 0.619 vs.\ 0.592). A small in-sample proxy (1/8 of A) shows classic over-optimization: its own score climbs to 0.941 while the half-B judges stop improving after 4,096 simulations (0.611, then 0.610). A leak-free proxy trained on 1/8 of the data beats an in-sample proxy with 8$\times$ the data on both realized indices (0.668 vs.\ 0.628 and 0.637 vs.\ 0.592 at 16,384 simulations).

The paper's own self-play pipeline on half A (2 seeds per cell, 300K episodes each, the behavioral-cloning bootstrap and the GD opponent trained on half A) shows the same split. Raising training simulations from 200 to 800 moves the in-sample agents' half-B judges from 0.686 to 0.607 and their degenerate rate from 27\% to 75\%, and lowers both realized indices by 0.03; the out-of-fold agents gain 0.016 under the same judges at a 3--4\% degenerate rate.

Two diagnostics that did not detect the problem: the per-draft disagreement of a 4-seed ensemble trained on the same statistics stays between 0.005 and 0.007 at every search pressure (seeds share the leak), and pessimistic lower-confidence-bound search using that disagreement lifts the in-sample ensemble's half-B judges by at most 0.012 (0.639 $\to$ 0.651), well short of the out-of-fold ensemble (0.661). Held-out calibration slope did detect it, which is why the main paper reports it for every value function and judge.

\section{Composition Blind Spot and Corrected References}
\label{sec:compjudge}

\paragraph{Audit} A drafter that picks the available hero with the highest win rate scored 0.677 under the production seed-selection judge (a realized index on 90 days of games), above both trained policies (0.644, 0.650), although 55\% of its teams were degenerate. Table~\ref{tab:compaudit} measures every reference on the 1,943,338 snapshot games, which none of them trained on, as realized minus predicted win rate per team type (no healer, no frontline, three or more of a stacking role; exclusive, in that order). \paragraph{Selection or cause} Weaker players might field broken teams. We joined 897,779 games (snapshot games from June 2025 and post-snapshot games with all ten player records) to causal per-player, per-hero skill estimates from the previous day (a Gaussian-process model over each player's heroes; skill is estimated with degenerate-team games left out, so it cannot absorb the penalty itself) and to pick order. Degenerate teams are weaker (summed skill $-$0.3pp vs.\ +1.0pp for normal teams), but matchmaking pairs them with weaker opponents too. Against RN, the penalty is $-$4.79pp with no controls, $-$4.62pp with the team skill difference, $-$4.83pp adding skill by pick position and first-pick side, and $-$4.65pp adding party and never-played-hero counts (bootstrap SE 0.32pp; SE of the change 0.04pp). At most about 0.2pp of the 4.8pp is selection on these measures. Unmeasured differences between players remain possible.

\paragraph{Correction} For each reference $J$ we fit $p^\ast = \sigma(\mathrm{logit}\,p_J + \beta_J^\top(s_\text{own} - s_\text{opp}))$ with $s$ the three structure indicators (non-exclusive) and $p_J$ fixed, on the 260,539 post-snapshot no-drift games, using predictions $J$ makes for games it did not train on (above). The fitted no-healer, no-frontline, and stack coefficients (logits) are $-$0.10, $-$0.13, $-$0.14 (gN); $-$0.21, $-$0.20, $-$0.38 (gN-naive); $-$0.18, $-$0.25, $-$0.38 (RN); $-$0.21, $-$0.19, $-$0.36 (QM2026). The correction is antisymmetric in the two teams, so symmetrized scores stay symmetrized. A version with the skill controls gives coefficients within 0.14 and over-corrects the snapshot games by 0.8pp, consistent with little selection; we use the plain fit. On games after the 2.55.17 balance patch the penalty is smaller and the corrected references over-charge degenerate teams by about 2pp. The terms are learned from human degenerate teams, 93\% of which have exactly one defect (68\% no healer); the MCTS agents' degenerate teams have exactly one defect in 94--100\% of cases and are 80--98\% no-healer teams, the best-covered type. A structure nobody fields, such as five tanks, receives only the sum of its indicators.

\paragraph{Effect on the results} Under the corrected references, the benchmark contrasts behind sim scaling, the feature gap, training length, and the operating point change by at most 0.007 (Table~\ref{tab:compclaims}): GD opponents sampled at temperature 1 field degenerate teams too, so the correction charges both sides of the MCTS benchmark. The leak-control contrasts sharpen by up to 0.011 because the leaky 800-simulation agent fields 27\% degenerate teams. In the tournament the constrained agents gain (constrained vs.\ unconstrained MCTS 0.497 $\to$ 0.513, masked vs.\ unmasked greedy 0.500 $\to$ 0.511, both $\pm$0.004), the featureless MCTS agent falls from first to second (0.602 $\to$ 0.607, behind constrained MCTS at 0.597 $\to$ 0.612), the Gourdeau estimator (45\% degenerate) drops from 0.534 to 0.521, and MCQ from 0.370 to 0.295. Rank agreement of the Quick Match judges within the top six falls (0.89 $\to$ 0.66), because the correction moves constrained MCTS ahead of K and the Gourdeau estimator behind both greedy agents, orderings those judges do not share.

\section{Judge Attenuation}
\label{sec:atten}

An independent judge is a noisier model than the value function an agent optimized, so a real gain shrinks under it. As a benchmark for that shrinkage we regress each judge's prediction on the value function's prediction over the 38,869 test replays, which neither trained on (Table~\ref{tab:atten}). With no over-optimization, a gain $d$ under the value function should appear as about slope $\times\, d$ under the judge, if the value function's errors on agent drafts resemble its errors on human drafts. The submitted value function's statistics contain the test games, so its slopes are a rough guide.

\section{Offline RL: Sweeps and Robustness}
\label{sec:cqlrobust}

The main paper's Table~IV shows one or two cells per offline-RL family. The full sweeps, trained on our split with naive (identity) features unless noted and selected on validation games, all end at an anchored policy. CQL across $\alpha \in \{0.1, 0.5, 1, 2, 5\}$ (5 seeds $\times$ 1000 drafts each): 97.5--99.7\% healer and 1.9--9.3\% degenerate, best at $\alpha = 2$ (99.6\%, 1.9\%). BC-regularized CQL across $\beta \in \{0.1, 0.5, 1, 2\}$: near-perfect safety (99.5--100\% healer), high GD agreement (70--74\%), negative synergy. MCQ across $\tau \in \{0.4, \dots, 0.8\}$: for $\tau \geq 0.6$ the penalty is inactive and the policy uses the same 8 heroes regardless of context; $\tau = 0.5$ gives the dead-network policy of the main text (all 128 units of hidden layer 3 and 255 of 256 of layer 2 output zero on 200,000 held-out states; at $\tau = 0.6$, 126 of 128 units of layer 3 are dead; a CQL $\alpha = 1$ control has 26 and 13 dead units). IQL across a $\tau \times \beta$ grid of six cells: statistically identical cells, advantage weights 0.995--0.999, Q-network held-out loss 0.6948 against $\ln 2 = 0.6931$ for a constant.

\textit{Capacity and target-update robustness.} At $\alpha = 1$ we crossed three network sizes (256$\to$128$\to$64, 512$\to$256$\to$128, 1024$\to$512$\to$256) with five target-network update rates ($\tau_{\text{target}} \in \{0.001, 0.005, 0.01, 0.05, 0.1\}$; 200 drafts each). Across all 15 configurations the collapse signals are stable: healer 98.5--100\%, degenerate 1.0--5.0\%, 46--57 distinct heroes, entropy 4.44--4.59 bits, GD agreement 68.4--73.9\%, synergy $-$0.13 to +0.03. No configuration is interaction-aware, and the update rate is inert, as expected with Monte Carlo returns (no bootstrapping).

\textit{CQL with enriched features.} Trained on out-of-fold enriched transition features and evaluated with deploy statistics, enriched CQL behaves like naive CQL: 3.4--3.6\% degenerate, synergy $-$0.18, entropy 4.65--4.67 bits, GD agreement 68.4--70.4\%. Under the independent references these agents score 0.49--0.52 against behavioral-cloning opponents.
